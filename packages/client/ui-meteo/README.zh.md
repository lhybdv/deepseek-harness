# @deepseek-ai/dsh-client-ui-meteo

[English](README.md) | 中文

## 概述

气象面板 **风引 WindPilot** 的浏览器侧：一个全局语料库页面，经 `meteo` Remote 命名空间索引、检索并展示专业资料；外加一个按地址打开该索引中某一段的右侧 Sidebar 引用 tab。两者都只读 `meteo` Remote 命名空间。

<a id="what-it-registers"></a>
## 注册了什么

- **面板行与页面**：`sidebar.panellist` 中 id 为 `meteo-corpus`、order 30 的一行，标签取自 `meteo` 命名空间，图标用共享的仪表盘字形；以及 root 作用域 `main` 中以同一 key 注册的正文。同一个 id 寻址这两处，因此一行不可能指向不存在的正文。id 保持 `meteo-corpus`，因为它是**寻址键而非标签**；两处名称刻意不同：面板行承载**功能**（可引用资料的索引），页面标题承载**产品名**——扫一眼面板列表的人该知道这行是干什么的，而不是这个部署叫什么。页面是全局而非会话作用域，因为语料库不是会话状态：整个部署共用一座索引。
- **引用类型**：`ctx.sidebarRightTabs.register(...)`，kind 为 `meteo-citation`，id 为 `@deepseek-ai/dsh-client-ui-meteo/citation`，档位 `builtin`，pattern 为 `dsh-resource://meteo/citation/**`，另有一个 order 30 的引导页入口。正文是以该 id 为键的 `sidebar.right.pane.tab` slot。没有别的已注册类型认领这个 scheme，因此该定义不需要 `canOpen`。

`src/client/` 下八个源文件：`address.ts`（引用地址）、`definition.ts`（类型是什么）、`face.ts`（Remote 绑定）、`CorpusPage.tsx`（页面）、`CitationTab.tsx`（证据正文）、`MeteoPanelIcon.tsx`（面板字形）、`locales.ts`（它说什么）、`index.ts`（接线）。

<a id="the-corpus-page"></a>
## 语料库页面

三个面向同一个绑定 face 的界面，各自持有 pending 状态，因此只有正在进行的那个调用会禁用对应的控件。

| 界面 | 动作 | 回答 |
|---|---|---|
| 文档 | 挂载时列出，**重新读取**再次列出 | 每份文档的标题、段数、体积、来源与索引时间，附**查看分段**（按需读取每一段）与**删除**。 |
| 上传资料 | 一次多选文件，索引前一直处于待索引状态；没有待索引文件时**索引**保持禁用 | 索引返回的新文档列表，外加每个被拒来源一行。文档标题取**文件名去掉页面解码时所用后缀**——后缀描述的是文件，不是资料本身。页面会拒绝自己无法解码的文件——点明文件与原因——并让被索引拒绝的来源留在待索引列表里，读者改好再发一次即可，不必再去找一遍文件。 |
| 检索 | 一个查询；查询为空白时**检索**保持禁用 | 带标题层级、字符区间与摘录的排序命中，每条附**查看证据**，点击后把该段原样读回并显示在该条命中下方。 |

页面保存的只是阅读状态：列表、最近一次索引的被拒项、最近一次检索的查询与命中、最近打开的那一段，以及各界面最近一次失败所答的消息。每个动作都用 Host 的答复替换本地状态，而不是就地修补，因此当索引把删除答为 `removed: false` 时列表原样不动——文档本来就已经不在了，而那正是读者想要的状态。

删除会同时丢弃该文档与所有指向它的命中，因此检索结果永远不会给出页面已不再列出的文档的证据。

**为什么证据读回页面、而不是开在右栏。** 右栏的 tab 席位是会话作用域的，而会话界面只在对话显示时挂载——本面板一旦被选中就替换了它。因此从全局面板调用 `ctx.sidebarRight.openResource` 会抛 `no session surface is mounted`。改为经同一个回答检索的命名空间把该段读回来，在任何显示本面板的地方都能用。

<a id="the-citation-tab"></a>
## 引用 tab

`meteo-citation` 类型为确有会话的界面而注册：一条引用就是一个资源地址 `dsh-resource://meteo/citation/<docId>/<ordinal>`，打开它会把该段读进右栏的一个 tab。文档 id 作为一个路径段整体百分号编码，因为 id 是语料库自己生成的不可读文本，可能含有 `/`；同一地址打开两次就是同一个 tab，因为地址就是内容身份。

正文在其标题层级与字符区间之下原样呈现该段——这正是读者据以把结论与模型所引段落对照的东西。三种答复被区分开来：该段本身；`meteo/chunk-not-found`，这是一种被回答而非被重试的删除，因此 tab 会说明该引用已不存在；以及其他任何失败，连同其消息一并报告。类型本就不该认领的地址会被直接拒绝，而不会被当作别的某段读出来。

`citationAddress` 作为该 scheme 的写入方导出。目前还没有任何东西组装它：展示引用的咨询卡片已经存在并已注册，但它的引用行还不会打开这个类型，把两者接起来属于暂缓事项（见「已知限制与暂缓事项」）。

<a id="model-experience"></a>
## 模型体验

无，因为本包在浏览器里绘制语料库页面与引用查看器，不注册任何面向模型的内容。

#### KV Cache 影响

无；语料库读取与检索经 Remote 传输，不会组装模型请求。

## 已知限制与暂缓事项

<a id="known-limitations-and-deferred-work"></a>
- **只支持文本文件。**选择器在浏览器里读取 `.md`、`.markdown`、`.txt`、`.text`、`.json`、`.csv`、`.log`、`.yaml`、`.yml`，其余按文件名拒绝；`docx`、`pdf` 与表格格式需要本部署未附带的服务端抽取器，而把它们的字节当文本索引比拒绝更糟。
- **索引是全局的。**每个会话看到的是同一座语料库，没有按会话或按用户的隔离；页面在删除前不做确认。
- **没有重排，也没有高亮。**页面按索引自己的排序展示命中，用索引截断后的摘录；咨询路径的重排属于工具，不属于本页面。
- **引用 tab 暂时还没有开启方。**类型与查看器已完备并有单测覆盖，但唯一能打开它的界面是对话，而本该打开它的咨询卡片属于暂缓事项。

<a id="dev-note"></a>
### 开发备注

<details>
<summary>维护者工作上下文——点击展开</summary>

引用地址被刻意设计为资源地址，而不是以 tab id 为键的 store：这使打开操作幂等、能在刷新后存活，并且页面与 tab 之间不需要任何旁路通道。

</details>

**运行时不变量：** 不发布 companion。页面状态可由命名空间的答复推导，tab 状态是每个地址一次的分段读取；两者都没有以可能与另一插件不一致的方式观测他人状态。
